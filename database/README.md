# Database Architecture & Version-Controlled Reference Guide

This directory contains version-controlled reference DDL, view definitions, reference seed scripts, and test scenario definitions for **AI Revenue Recovery & Receivables Intelligence**.

> [!IMPORTANT]
> **AUTHORITATIVE SOURCE OF TRUTH**: The live Supabase PostgreSQL database is the sole authoritative business source of truth.
> The files in this `database/` directory are for version-controlled documentation, reference DDL, and environment reproduction. They MUST NOT be executed blindly against the live Supabase database.

---

## 1. Source-of-Truth Hierarchy

```
Live Supabase PostgreSQL Database (Authoritative Business Truth)
        ↓
Node.js / Express Backend (Service Role Access)
        ↓
database/ Repository Directory (Version-Controlled Reference DDL)
```

| Data Domain | Source of Truth | Notes |
|---|---|---|
| **Invoice Amount** | Live Database Truth (`invoices.amount`) | Immutable financial record |
| **Payments Received** | Live Database Truth (`payments.amount`) | Gateway/Bank transaction truth |
| **Outstanding Balance** | Calculated Truth (`amount - paid_amount`) | Deterministic arithmetic |
| **Days Overdue** | Calculated Truth (`CURRENT_DATE - due_date`) | Dynamic view calculation |
| **AI Priority Score** | Recommendation | Suggested queue order generated by rules/agents |
| **AI Exception Hypothesis** | Reasoning | Suggested explanation (e.g. "Possible 10% TDS") |
| **Policy Enforcement** | TypeScript Policy Engine | Hard guardrail blocking illegal financial actions |

## 2. Core Tables Reference

1. **`businesses`**: Onboarded merchant accounts.
2. **`customers`**: Customer profiles, credit limits, risk assessment scores (`risk_score`).
3. **`invoices`**: Receivable invoices, amounts, paid amounts, status, due dates.
4. **`payments`**: Payment receipts, transaction methods, reference numbers.
5. **`payment_allocations`**: Mappings connecting payment receipts to specific invoices.
6. **`communications`**: Inbound & outbound call notes, emails, portal messages.
7. **`promises`**: Customer commitments to pay specific amounts by agreed dates (`pending`, `fulfilled`, `broken`).
8. **`reconciliation_exceptions`**: Payment mismatches, short pays, fees (`open`, `investigating`, `resolved`).
9. **`agent_runs`**: Agentic execution lifecycle logs (`running`, `completed`, `failed`).
10. **`agent_decisions`**: Specialist agent outputs, reasoning, confidence scores.
11. **`actions`**: System actions queued by agents (`pending`, `executed`, `blocked`).
12. **`policy_decisions`**: Policy guardrail evaluation records (`allowed`, `violation_reason`).
13. **`audit_logs`**: Immutable audit logs of all user, API, and system operations.

## 3. Dynamic Working View

### `invoice_working_view`
A real-time database view computing:
- `outstanding_amount` (`amount - paid_amount`)
- `days_overdue` (`CURRENT_DATE - due_date`)
- `priority` (`HIGH`, `MEDIUM`, `LOW`)
- `active_promises_count`
- `open_exceptions_count`

## 4. Foreign Key Relationships

1. `customers.business_id` → `businesses.id`
2. `invoices.business_id` → `businesses.id`
3. `invoices.customer_id` → `customers.id`
4. `payments.business_id` → `businesses.id`
5. `payments.customer_id` → `customers.id`
6. `payment_allocations.payment_id` → `payments.id`
7. `payment_allocations.invoice_id` → `invoices.id`
8. `promises.invoice_id` → `invoices.id`
9. `promises.customer_id` → `customers.id`
10. `communications.invoice_id` → `invoices.id`
11. `communications.customer_id` → `customers.id`
12. `reconciliation_exceptions.invoice_id` → `invoices.id`
13. `reconciliation_exceptions.payment_id` → `payments.id`

## 6. Future Schema Modification Rules

If a new table or column is required in a future phase:
1. Explain the operational necessity.
2. Check if an existing table can accommodate the data.
3. Inspect live Supabase schema.
4. Draft explicit DDL proposal.
5. Obtain explicit approval before execution.
6. Apply migration safely in Supabase.
7. Verify live database schema.
8. Update repository SQL reference files and `database/README.md`.
