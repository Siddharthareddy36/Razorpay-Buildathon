# Action Planner — Design & Architecture Specification

## 1. Executive Overview & Mission

The **Action Planner** bridges the gap between intelligence recommendations generated by the Multi-Agent Supervisor / Specialist Agents and operational recovery actions executed by **n8n**. It translates agentic findings into strongly typed, policy-guarded `ActionPlan` objects.

## 3. Action Eligibility & Safety Rules (Part 3)

1. **PAID_INVOICE_STOP**: If `outstanding_amount <= 0.001` or status = `PAID` $\rightarrow$ actionType = `NOTIFY_OPERATOR`, policyDecision = `REJECTED`, reason = *"Invoice is fully paid in authoritative ledger. Recovery action halted."*
2. **ACTIVE_DISPUTE_STOP**: If status = `DISPUTED` $\rightarrow$ actionType = `CREATE_FINANCE_REVIEW_TASK`, policyDecision = `HUMAN_REVIEW`, `requiresApproval = True`.
3. **AMBIGUOUS_QUERY_STOP**: If intent = `UNKNOWN` $\rightarrow$ actionType = `CREATE_FINANCE_REVIEW_TASK`, policyDecision = `HUMAN_REVIEW`, `requiresApproval = True`.
4. **UNSAFE_MUTATION_BLOCK**: If query proposes balance write-off or accounting waiver $\rightarrow$ actionType = `NOTIFY_OPERATOR`, policyDecision = `REJECTED`, `requiresApproval = False`.
5. **RECONCILIATION_TDS_RULE**: If reconciliation hypothesis = `TDS` $\rightarrow$ actionType = `REQUEST_TDS_DOCUMENT`, policyDecision = `HUMAN_REVIEW`, `requiresApproval = True`.
6. **P2P_BROKEN_PROMISE_RULE**: If promise state = `BROKEN` $\rightarrow$ actionType = `SEND_PAYMENT_REMINDER`, priority = `HIGH`, `requiresApproval = False` (auto-approved if policy permits).

---

## 4. Human Approval Model (Part 4)

- **LOW-RISK (`SEND_PAYMENT_REMINDER`)**: Auto-approved (`requiresApproval = False`) ONLY if policyDecision = `APPROVED`.
- **SENSITIVE (`REQUEST_TDS_DOCUMENT`, `ESCALATE_COLLECTION_CASE`)**: `requiresApproval = True`, `approvalStatus = "PENDING_APPROVAL"`. Manual operator sign-off is mandatory before side-effect dispatch.
- **UNSAFE MUTATION**: Policy decision = `REJECTED`. Cannot be executed.
